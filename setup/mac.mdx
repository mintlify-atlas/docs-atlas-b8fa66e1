Polyphase builds and runs natively on Apple Silicon (arm64) and Intel (x86_64) Macs. Rendering goes through Vulkan on top of MoltenVK, the window and input layer is native Cocoa, and audio uses CoreAudio. The shipped editor is a universal binary. A source build targets the Mac it runs on unless you set `MAC_ARCH` (see the [Architectures](#architectures-apple-silicon-intel-universal) section below).

## Required Tools

| Install | Needed for | Verify with |
|---------|-----------|-------------|
| **Xcode Command Line Tools** (`clang`, `make`, `lipo`, `codesign`) | Everything | `xcode-select -p` prints a path |
| **Homebrew** with `cmake` and `python3` | libgit2 prebuild, asset-stub generator, native addons with CMake | `cmake --version`, `python3 --version` |
| **Vulkan SDK 1.4.357.1** (LunarG, macOS) | Editor and every game build: MoltenVK, loader, `glslc`, shaderc, SPIRV-Cross | `vulkaninfo --summary` lists `driverName = MoltenVK` |
| **devkitPro pacman** with `wii-dev` and `3ds-dev` | Packaging for Wii, GameCube, and 3DS | `powerpc-eabi-g++ --version`, `arm-none-eabi-g++ --version` |
| **`libogc2`**, `libogc2-libdvm`, `gamecube-tools-git` | Packaging for **GameCube** (libogc2, not the stock libogc) | `ls /opt/devkitpro/libogc2/gamecube/lib` |
| Rosetta 2 *(Apple Silicon only, optional)* | Running Intel slice of a universal build; `cwavtool` for 3DS banners | `arch -x86_64 /usr/bin/true` |
| Homebrew `curl` *(optional)* | `wss://` connections from the editor | `ls /opt/homebrew/opt/curl/lib` |

<Note>
  Not needed on macOS: Docker (macOS targets cannot be built in a container and the console toolchains run natively), Visual Studio, and MSYS2.
</Note>

<Steps>

### Pull Submodules

```bash
git submodule update --init --recursive
```

### Install Xcode Command Line Tools

```bash
xcode-select --install
```

A full Xcode installation also works. Nothing in the Polyphase build system uses Xcode projects.

### Install Homebrew Build Helpers

```bash
brew install cmake python3
```

Homebrew lives in `/opt/homebrew` on Apple Silicon and `/usr/local` on Intel Macs. The editor looks in both locations when spawning build tools.

<Note>
  `cmake` is only used to build the bundled `libgit2` once (`Tools/prebuild_mac.sh`) and by native addons that ship a CMake project. The engine itself builds with `make`. The system `curl` on macOS has no WebSocket support; for `wss://` connections run `brew install curl` and export `POLYPHASE_LIBCURL=/opt/homebrew/opt/curl/lib/libcurl.4.dylib` (`/usr/local/opt/curl/lib/libcurl.4.dylib` on Intel).
</Note>

### Install the Vulkan SDK

One installer covers both architectures. The SDK's dylibs and static libraries are universal, so the same install serves native, Intel, and universal builds.

Download the macOS SDK version **1.4.357.1** from [https://vulkan.lunarg.com/sdk/home#mac](https://vulkan.lunarg.com/sdk/home#mac) and install it to `~/VulkanSDK/1.4.357.1`.

Add the following to your `~/.zshrc` (replace `1.4.357.1` with the version you installed). `VULKAN_SDK` must point at the `macOS` subdirectory, which holds `include/`, `lib/`, and `bin/`:

```bash
export VULKAN_SDK=$HOME/VulkanSDK/1.4.357.1/macOS
export PATH=$VULKAN_SDK/bin:$PATH
export VK_ICD_FILENAMES=$VULKAN_SDK/share/vulkan/icd.d/MoltenVK_icd.json
export VK_DRIVER_FILES=$VULKAN_SDK/share/vulkan/icd.d/MoltenVK_icd.json
export VK_ADD_LAYER_PATH=$VULKAN_SDK/share/vulkan/explicit_layer.d
```

Reload your shell and verify:

```bash
source ~/.zshrc
vulkaninfo --summary | grep -E "deviceName|driverName"
```

Expected output includes `driverName = MoltenVK` and your GPU name. `which glslc` should print a path inside the SDK.

### Install devkitPro Toolchains

**Step 1 — Install devkitPro Pacman:**

Download the `.pkg` from the [devkitPro pacman releases](https://github.com/devkitPro/pacman/releases) and install it. It supports Intel and Apple Silicon Macs, creates `/opt/devkitpro`, and sets `DEVKITPRO`, `DEVKITPPC`, `DEVKITARM` in `/etc/profile.d/devkit-env.sh`.

**Step 2 — Install Wii and 3DS toolchains:**

`wii-dev` is required for GameCube too — it provides devkitPPC (`powerpc-eabi-g++`), which the GameCube build uses even though GameCube libraries come from `libogc2`.

```bash
sudo dkp-pacman -S wii-dev 3ds-dev
```

Restart the terminal, then verify:

```bash
powerpc-eabi-g++ --version
arm-none-eabi-g++ --version
```

**Step 3 — Install libogc2 for GameCube builds:**

Trust the libogc2 signing key:

```bash
sudo dkp-pacman-key --recv-keys C8A2759C315CFBC3429CC2E422B803BA8AA3D7CE --keyserver keyserver.ubuntu.com
sudo dkp-pacman-key --lsign-key C8A2759C315CFBC3429CC2E422B803BA8AA3D7CE
```

<Note>
  If `--recv-keys` fails with *"No route to host"* (HKP port 11371 is often blocked), fetch the key over HTTPS instead:

  ```bash
  curl -o ~/Downloads/libogc2-key.asc "https://keyserver.ubuntu.com/pks/lookup?op=get&search=0xC8A2759C315CFBC3429CC2E422B803BA8AA3D7CE"
  sudo dkp-pacman-key --add ~/Downloads/libogc2-key.asc
  sudo dkp-pacman-key --lsign-key C8A2759C315CFBC3429CC2E422B803BA8AA3D7CE
  ```
</Note>

Add the libogc2 repository to `/opt/devkitpro/pacman/etc/pacman.conf` **above** the existing `[dkp-libs]` entry. This is file content, not commands — both `Server` lines are mirrors and both belong in the file:

```ini
[libogc2-devkitpro]
Server = https://packages.libogc2.org/devkitpro/macos/$arch
Server = https://packages.extremscorner.org/devkitpro/macos/$arch
```

Sync and install:

```bash
sudo dkp-pacman -Syuu
sudo dkp-pacman -S gamecube-tools-git libogc2 libogc2-libdvm
```

Verify:

```bash
ls /opt/devkitpro/libogc2/gamecube/lib
```

### Run the Prebuild Script

```bash
bash Tools/prebuild_mac.sh
```

This checks that `VULKAN_SDK`, `cmake`, and the Command Line Tools are present, then builds `libgit2`, compiles shaders, and writes the embedded-asset stubs for `Standalone/Generated/`.

### Build and Run the Editor

**Terminal:**

```bash
cd Standalone
make -f Makefile_Mac_Editor -j$(sysctl -n hw.ncpu)
cd ..
Standalone/Build/Mac/PolyphaseEditor
```

**VS Code:**

Open the repo root, install the **C/C++ Extension Pack**, and pick **Polyphase Editor - Mac** in Run and Debug. It runs the **Make Standalone Editor - Mac** task, then launches under `lldb` with the repo root as the working directory.

<Warning>
  Always run the editor binary from the **repository root directory** so that `Engine/Assets` and `Engine/Shaders` resolve correctly. The editor's Ctrl-based hotkeys also accept the Command key (⌘S saves, ⌘Z undoes). F-keys require **Use F1, F2, etc. keys as standard function keys** in System Settings → Keyboard, or the Fn key.
</Warning>

</Steps>

## Architectures: Apple Silicon, Intel, Universal

The Makefiles take a `MAC_ARCH` variable on the command line or in the environment:

| `MAC_ARCH` | Builds | When to use |
|------------|--------|-------------|
| `native` (default) | This Mac's arch (`arm64` on Apple Silicon, `x86_64` on Intel) | Day-to-day development |
| `universal` | arm64 + x86_64 in one binary | What the release `.dmg` ships — about twice the compile time |
| `arm64` / `x86_64` | A single slice, cross-compiled if not the host's arch | Testing the other architecture |

```bash
# Universal binary build
MAC_ARCH=universal bash Tools/prebuild_mac.sh
make -C Standalone -f Makefile_Mac_Editor -j$(sysctl -n hw.ncpu) MAC_ARCH=universal
```

<Note>
  On Apple Silicon, install Rosetta 2 once to run the Intel slice of a universal build:

  ```bash
  softwareupdate --install-rosetta --agree-to-license
  arch -x86_64 Standalone/Build/Mac/PolyphaseEditor
  ```

  `lipo -archs <binary>` shows which slices a file contains.
</Note>

## Packaging a macOS App Bundle

The **macOS (App Bundle)** build target compiles a Mach-O with `Makefile_Mac_Game` and wraps it into `Packaged/Mac/<Project>.app` with MoltenVK and the Vulkan loader inside `Contents/Frameworks`. It requires the same tools as building the editor (Xcode Command Line Tools + Vulkan SDK); nothing extra. macOS targets can only be built on a macOS host — the "Use Docker" option is disabled for them.

Every bundle is at least ad-hoc signed so it runs on the machine that built it. For distribution, set a **Signing Identity** (`Developer ID Application: ...`) in the profile's Target Options, optionally enable **Notarize** with a keychain profile created by `xcrun notarytool store-credentials`, and tick **Create .dmg**. Details are in the [Desktop Platforms guide](/platforms/desktop).

To ship the editor itself:

```bash
bash Installers/build_app_mac.sh      # produces dist/Polyphase.app
bash Installers/build_dmg_mac.sh      # wraps it into dist/PolyphaseEditor-<version>-macos-<arch>.dmg
```

## Packaging a 3DS Installable (.cia)

The plain **Nintendo 3DS** build target needs nothing beyond `3ds-dev` above. The **Nintendo 3DS (CIA)** target, which produces an installable HOME Menu title, requires additional tools that devkitPro does not ship. None are needed unless you use that target.

| Tool | Needed for | Where it comes from |
|------|-----------|---------------------|
| `makerom` | The `.cia` (required) | [3DSGuy/Project_CTR releases](https://github.com/3DSGuy/Project_CTR/releases), `makerom-v0.19.0-macos_arm64.zip` (Intel Macs: `macos_x86_64` zip) |
| `bannertool` | HOME Menu banner and tune (optional) | No macOS binary is published. Build from source: [carstene1ns/3ds-bannertool](https://github.com/carstene1ns/3ds-bannertool), `bannertool-1.2.3.tar.gz`, then `make` and set the path in Preferences |
| `cwavtool` | DSP-ADPCM tune encoding (optional, experimental) | [PabloMK7/cwavtool releases](https://github.com/PabloMK7/cwavtool/releases), `cwavtool.zip` → `mac-x86_64/cwavtool` (runs under Rosetta on Apple Silicon) |
| Python 3.12 + pycgfx | 3D scene banners (optional) | `brew install python@3.12` and [skyfloogle/pycgfx](https://github.com/skyfloogle/pycgfx) |

**Easiest:** in the editor open **Preferences → External → Launchers**, scroll to **3DS CIA Tools**, and click **Download makerom + bannertool + cwavtool**. `makerom` and `cwavtool` are fetched from the release pages above into `~/Library/Application Support/PolyphaseEditor/Tools/3DS`, made executable, and picked up immediately (`bannertool` is skipped with a warning on macOS — see the table). Downloaded binaries are quarantined by Gatekeeper; if one refuses to run, `xattr -d com.apple.quarantine <tool>`.

**Manual:** extract the binaries, `chmod +x makerom bannertool cwavtool`, and either copy them into `/opt/devkitpro/tools/bin`, put them somewhere on `PATH` such as `~/.local/bin`, or set the path fields in the same Preferences page.

**3D banners** additionally need Python 3 with pip. Click **Install pycgfx** in the same Preferences page (it downloads pycgfx, pinned to a fixed commit, and runs `python3 -m pip install --user gltflib pillow`).

## Where the Editor Keeps Its Files

| What | Path |
|------|------|
| Preferences, hotkey and input presets, downloaded tools | `~/Library/Application Support/PolyphaseEditor/` |
| Game saves when the project directory is read-only (e.g. inside a `.app`) | `~/Library/Application Support/<Project>/Saves/` |
| Addon-recovery sentinel | `~/Library/Application Support/Polyphase/` |

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| `Failed to find platform surface extension` / `No physical device found` | Export `VK_DRIVER_FILES` (see above) or install the SDK under `~/VulkanSDK` so the editor can find it. `vulkaninfo --summary` must list MoltenVK. |
| `ERROR: VULKAN_SDK is not set` from `prebuild_mac.sh` or `make` | The shell did not load `~/.zshrc` (SSH, CI, a script). Export `VULKAN_SDK=$HOME/VulkanSDK/<ver>/macOS` explicitly. |
| `dyld: Library not loaded: @rpath/libvulkan.1.dylib` | The editor was linked against a `VULKAN_SDK` that has since moved. Rebuild with the current `VULKAN_SDK`, or set `DYLD_LIBRARY_PATH=$VULKAN_SDK/lib`. |
| Shaders fail to compile in `prebuild_mac.sh` | `VULKAN_SDK` must point at `~/VulkanSDK/<ver>/macOS`, not the version directory above it. Check `which glslc`. |
| `MAC_ARCH ... cleaning ...` lines and a long rebuild | You changed the architecture. The Makefiles discard objects of the other arch on purpose. `MAC_ARCH must be native, arm64, x86_64 or universal` means a typo in the value. |
| `powerpc-eabi-g++: command not found` when packaging | `wii-dev` is not installed, or the terminal was not restarted after installing devkitPro. Run `dkp-pacman -Q` to list what is installed. |
| GameCube link errors about missing `libogc2` | Step 3 of the devkitPro section was skipped. The stock `libogc` from `wii-dev` is not enough for GameCube. |
| `wss://` connections report "no WebSocket support" | Install Homebrew curl and export `POLYPHASE_LIBCURL` as described above. |
| Gatekeeper blocks a downloaded editor or game | Ad-hoc signed builds are not notarized. Right-click → Open once, or `xattr -dr com.apple.quarantine <app>`. |
| Debugging | `lldb Standalone/Build/Mac/PolyphaseEditor` from the repo root, or VS Code with the CodeLLDB extension pointing at the same binary with `cwd` set to the repo root. |
