The Polyphase visual editor is a full-featured scene authoring tool that runs on Windows, Linux, and macOS. It provides a scene hierarchy, asset browser, properties inspector, and 3D viewport — all in a single window. The editor can also run in **headless mode** for automated asset cooking and game building in CI/CD pipelines and Docker containers.

## Panels

<CardGroup cols={2}>
  <Card title="Scene Hierarchy" icon="sitemap">
    Lists every node in the open scene as a tree. Right-click to add, duplicate, rename, or delete nodes. Drag nodes to re-parent them. Toggle visibility with **T**.
  </Card>
  <Card title="Assets Panel" icon="folder-open">
    Browses all assets in the current project. Right-click to create, import, rename, or delete assets. Supports scenes, materials, particles, textures, meshes, sounds, and more. Toggle visibility with **T**.
  </Card>
  <Card title="Properties Panel" icon="sliders">
    Inspects the selected node or asset. Lock the inspected object with **L**, navigate history with **Mouse4** / **Mouse5**. Toggle visibility with **N**.
  </Card>
  <Card title="Viewport" icon="eye">
    The 3D editing viewport. Hold **Right Click** to pilot the camera, use the gizmos to transform nodes, and access all viewport-specific hotkeys listed below.
  </Card>
</CardGroup>

## Headless Mode

Headless mode allows the editor to run without a graphical interface for automated asset compilation and game building. This is useful for CI/CD pipelines and Docker-based build environments.

<Note>
  Headless mode requires **both** the `-headless` flag **and** a `-project` path. Omitting either will prevent the editor from entering headless mode.
</Note>

### Command-Line Arguments

| Argument | Description | Example |
|----------|-------------|---------|
| `-headless` | Enables headless mode | `-headless` |
| `-project` | Path to the project file (`.octp`) | `-project MyGame/MyGame.octp` |
| `-build` | Target platform for compilation | `-build Linux` |
| `embedded` | Embed assets into the executable (optional, follows `-build`) | `-build Linux embedded` |

### Supported Build Platforms

| Platform | Output |
|----------|--------|
| `Linux` | Linux executable (`.elf`) |
| `Windows` | Windows executable |
| `GameCube` | GameCube DOL file |
| `Wii` | Wii DOL file |
| `3DS` | Nintendo 3DS ROM |
| `Android` | Android APK |

### Usage Examples

Build a Linux game with embedded assets:

```bash
./PolyphaseEditor.elf -headless -project "/path/to/MyGame.octp" -build Linux embedded
```

Build a GameCube game:

```bash
./PolyphaseEditor.elf -headless -project "/path/to/MyGame.octp" -build GameCube embedded
```

Build a 3DS ROM:

```bash
./PolyphaseEditor.elf -headless -project "/path/to/MyGame.octp" -build 3DS embedded
```

### Headless Build Process

When building in headless mode, the editor performs the following steps in order:

1. **Asset Cooking** — All assets are converted to platform-specific formats (`.oct` files) and saved to a `Packaged/` directory.
2. **Asset Registry** — An `AssetRegistry.txt` is generated listing all packaged assets.
3. **Asset Embedding** — When using the `embedded` flag, assets are compiled into C++ source files (`EmbeddedAssets.h` and `EmbeddedAssets.cpp`).
4. **Script Processing** — Lua scripts are either embedded as C++ code or copied to the output directory.
5. **Shader Compilation** — For Vulkan platforms, GLSL shaders are compiled to SPIR-V.
6. **Game Compilation** — The final executable or ROM is compiled using the platform-specific toolchain.

<Tip>
  For Docker-based CI builds, see the [Docker](/setup/docker) guide. Headless mode is the mechanism the Docker build system uses internally for every `build-*` command.
</Tip>
