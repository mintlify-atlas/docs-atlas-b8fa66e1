Polyphase Engine supports C# as a first-class scripting language alongside Lua. C# sources compile with the latest **Roslyn** compiler and transpile to Lua via a vendored [CSharp.lua](https://github.com/yanghuan/CSharp.lua), so C# scripts run on every platform the engine ships — desktop, Android, Web, and all retro console targets — with **no .NET runtime in the shipped game**. The .NET SDK (version 8 or newer) is needed only while authoring. Generated `.lua` files are committed alongside the `.cs` sources so team members who don't touch C# never need the SDK.

## Enabling C# Scripting

<Tabs>
  <Tab title="New Project">
    In the **Create New Project** panel, click the **C#** option next to Lua. The editor scaffolds `Scripts/CSharp/` with a `Game.csproj`, `Game.sln`, and a sample script.
  </Tab>
  <Tab title="Existing Project">
    Go to **Tools → CSharp → Enable C# for This Project**, or tick **C# Scripting** in Project Settings. The editor creates `Scripts/CSharp/` with the same scaffolding.
  </Tab>
</Tabs>

If the .NET SDK is missing, the editor shows a guided install prompt (`winget install Microsoft.DotNet.SDK.8` on Windows).

### Opening the Solution in an IDE

Go to **Tools → CSharp → Open C# Solution**. The IDE is configured in **Preferences → External → Editors → C# IDE**:

| IDE | Behavior |
|-----|---------|
| Visual Studio (default) | Opens `Game.sln` |
| VS Code | Opens `Scripts/CSharp/` folder via the `code` CLI — needed for IntelliSense (requires the *C# Dev Kit* or *C#* extension) |
| Custom | Your own executable with `{editor}`, `{solution}`, `{project}`, `{folder}` placeholders |

The engine API is source-referenced by the `.csproj` so IntelliSense covers the complete Polyphase surface with doc comments. The path is refreshed automatically when the project opens on a different machine.

## Writing a Script

Derive from the appropriate base class and override only the lifecycle methods you need:

```csharp
using Polyphase;

public class SpinnerCS : Script3D
{
    [Property] public Vector3 AngularVelocity = new Vector3(0, 90, 0);
    [Property(Display = "Spin Enabled")] public bool Enabled = true;

    public override void Start()
    {
        Log.Debug("started on " + Name);
    }

    public override void Tick(float deltaTime)
    {
        if (!Enabled) { return; }
        AddRotation(AngularVelocity * deltaTime);  // bare call = the attached node
    }
}
```

### Script Base Classes

| Base Class | Use Case |
|-----------|---------|
| `Script` | Attach to any node type |
| `Script3D` | Nodes with a 3D transform |
| `ScriptWidget` | UI widgets — Widget API becomes bare calls |
| `Script<TNode>` | Concrete typed access, e.g. `Script<StaticMesh3D>` |

### Lifecycle Methods

Override only what you need: `Create` (before serialized properties apply), `Awake`, `Start`, `Tick(dt)`, `EditorTick(dt)`, `Stop`, `Destroy`, `BeginOverlap(other)`, `EndOverlap(other)`, `OnCollision(other, point, normal)`.

### Properties and Inspector Buttons

`[Property]` fields appear in the editor inspector, serialize with the scene, and survive hot reload. `[Button]` on a public parameterless method renders a clickable button in the inspector:

```csharp
[Property] public float Speed = 5.0f;
[Property(Display = "Is Active")] public bool Active = true;

[Button("Spin Faster", "Doubles the angular velocity")]
public void SpinFaster() { AngularVelocity = AngularVelocity * 2.0f; }
```

Save the file — the editor transpiles automatically (about one second) and hot-reloads the result. **Ctrl+R** rebuilds C# and reloads all scripts.

<Note>
  The file name must equal the class name. Script class names are global across Engine/Scripts, your Scripts/ folder, and every addon. The transpiler validates this and reports a conflict if two classes share a name.
</Note>

## Engine Types

Engine objects are not C# objects — a `Node3D`, `Button`, or `MaterialLite` value **is** the engine's Lua userdata, and the `Polyphase.*` classes are typed views over it. Handles are never constructed with `new`; they come from `[Property]` fields, node getters, `CreateNode(...)`, the `World`, or `AssetManager`.

| Area | Available Types |
|------|----------------|
| **Nodes** | `Node` → `Node3D` → `Primitive3D` → `Mesh3D` → `StaticMesh3D`, `SkeletalMesh3D`, `Camera3D`, `Spline3D`, lights, `Audio3D`, `Particle3D`, `TimelinePlayer`, … |
| **Widgets** | `Widget` → `Quad`, `Text`, `Button`, `Canvas`, `Slider`, `InputField`, `CheckBox`, `ProgressBar`, `ComboBox`, `ScrollContainer`, `Window`, … |
| **Assets** | `Asset` → `Texture`, `StaticMesh`, `SkeletalMesh`, `Material` → `MaterialLite`/`MaterialInstance`, `SoundWave`, `Font`, `Scene`, `ParticleSystem`, `DataAsset`, … |
| **Statics** | `Engine`, `Input`, `PlayerInput`, `Audio`, `Network`, `Renderer`, `TimerManager`, `Tween`, `SignalBus`, `SaveData`, `AssetManager`, `Http`, `WebSocket`, `Serial`, `Gizmos`, `LoadingMenu`, `WindowManager`, `Log`, `Debugger`, … |
| **Enums** | `AnchorMode`, `BlendMode`, `ShadingModel`, `Easing`, `NetFuncType`, `ButtonState`, `Key`, `Mouse`, `Gamepad`, … |

`is`, `as`, and casts work on engine values and honor the engine's class hierarchy (the runtime queries the node/asset itself, like Lua's `node:Is("StaticMesh3D")`).

## Networking

```csharp
public class Player : Script3D
{
    [Replicated(OnRep = nameof(OnHealthChanged))] public int Health = 100;
    [Property] [Replicated] public string DisplayName = "";

    [NetFunc(NetFuncType.Server, Reliable = true)]
    public void S_TakeDamage(int amount) { Health -= amount; }

    [NetFunc(NetFuncType.Multicast)]
    public void M_PlayHitFx() { /* runs everywhere */ }

    public void OnHealthChanged() { /* client-side callback after Health arrives */ }

    public void Hit(int amount) { InvokeNetFunc("S_TakeDamage", amount); }
}
```

## Calling Other Scripts (Including Lua)

```csharp
// C# → Lua script: dynamic call (no declarations needed)
object loot = Lua.Call(TargetChest, "Open", Name);
object count = Lua.Get(TargetChest, "lootCount");
Lua.Set(TargetChest, "isOpen", false);

// C# → Lua script: typed façade with IntelliSense
public class ChestHandle : Node3D
{
    /// @CSharpLua.Template = "{this}:Open({0})"
    public extern int Open(string instigatorName);
}
ChestHandle chest = Lua.As<ChestHandle>(TargetChest);
int n = chest.Open(Name);
```

Lua scripts can call public C# methods directly — every public instance method of a C# script is exposed on its wrapper table, so plain Lua calls it like any script method:

```lua
local loot = raiderNode:GetLoot()
raiderNode:Taunt("gg")
```

## How It Works

```
Scripts/CSharp/Foo.cs
    → (Roslyn + CSharp.lua transpiler)
    → Scripts/CSharp/Foo.lua      (committed alongside Foo.cs)
    → Scripts/CSharp/CSharpCore.lua  (BCL runtime bundle, trimmed to used modules)
```

From that point the normal Lua pipeline handles everything: hot reload, the script picker, packaging, and embedding. Packaged builds never contain `.cs` sources. Generated files carry a `~PolyphaseSharp~` marker — never edit them manually.

The transpiler lives at `Tools/PolyphaseSharp/`. The editor builds it on first use with `dotnet build` and reruns it whenever its sources change. Packaging aborts if C# compilation fails.

## Limitations

| Area | Limit |
|------|-------|
| **Numbers** | The engine's Lua VM is 32-bit on every platform: `double` **is** `float` at runtime. `long`, `ulong`, and `decimal` are unrepresentable (warned as PS2001). |
| **Threads / async** | No threads. `async`/`await` has no scheduler (warned as PS2002). |
| **Reflection** | Not supported — no metadata is exported. |
| **NuGet packages** | Binary NuGet packages (.IL) cannot be used. The pipeline transpiles C# *source* to Lua; there is no .NET runtime to execute IL in shipped games. Vendor pure-source libraries instead. |
| **`[Property]` types** | `int`, `short`, `byte`, `float`, `double`, `bool`, `string`, `Vector3`, `Color`, node handles, asset handles, and single-dimension arrays of those. |
| **Callbacks** | Single-cast delegates and lambdas only. `delegate += other` builds a multicast table the engine rejects. |
| **Networking** | `[Replicated]` fields cannot be arrays; `[NetFunc]` methods take at most 8 parameters. |
| **Script classes** | One per file, file name == class name, not generic, public parameterless constructor only. |
| **LINQ / collections** | Available (`List`, `Dictionary`, LINQ, etc.) but they allocate. Prefer plain loops in `Tick` on console targets. |
| **Performance** | C# runs at Lua interpreter speed — same tier as hand-written Lua scripts. It is a scripting layer, not a systems language. |

## When to Use C# vs Lua

<CardGroup cols={2}>
  <Card title="Use C# when…" icon="c">
    - Your team is more comfortable with C# syntax and IDE tooling
    - You want strong typing and IntelliSense for the full engine API surface
    - You need `[Property]` arrays and typed node/asset fields with inspector support
    - You prefer `[Button]`, `[Replicated]`, and `[NetFunc]` attributes over Lua conventions
    - You want to vendor pure-source C# helper libraries (pathfinding, noise, parsers)
  </Card>
  <Card title="Use Lua when…" icon="l">
    - You need maximum simplicity or rapid iteration without a compile step
    - The script is short and doesn't benefit from static types
    - You need native functionality unavailable in C# — use a native C++ addon and expose Lua bindings, then optionally add a thin C# façade with `@CSharpLua.Template`
  </Card>
</CardGroup>

<Note>
  The two languages interoperate freely. A C# script can call a Lua script's methods, a Lua script can call a C# script's public methods, and both can coexist in the same project and scene. You do not have to choose one globally — mix them per-file as needed.
</Note>
